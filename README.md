# AI-Generated Text Detector

A statistical-feature AI text classifier that runs **100% in the browser** — no server, no API, no data upload. Uses 11 hand-crafted NLP signals to estimate whether a passage was written by a human or generated by an LLM.

**Live demo:** [ai-content-detector.vercel.app](https://ai-content-detector.vercel.app)  
**Backend (optional):** [Render](https://render.com) or [Hugging Face Spaces](https://huggingface.co/spaces)

---

## How it works

### Features (11 signals)

| Feature | AI signal direction | Why |
|---|---|---|
| **Perplexity** | Low → AI | LLMs choose statistically predictable tokens |
| **Burstiness** | Low → AI | AI produces uniform per-sentence perplexity; humans vary |
| **Lexical Diversity** (TTR) | Low → AI | AI reuses phrases and patterns |
| **Avg Sentence Length** | High → AI | LLMs favour longer, more complete sentences |
| **Sentence Length Variance** | Low → AI | Human writing mixes short punchy lines with long ones |
| **Avg Word Length** | High → AI | Formal/jargon-heavy register is an LLM tell |
| **Stopword Ratio** | Low → AI | Formal AI text uses fewer function words |
| **Punctuation Density** | — | AI over/under-punctuates in detectable patterns |
| **Repetition Score** | High → AI | Repeated bigrams are common in template-style AI text |
| **POS Entropy** | Low → AI | Grammatically uniform output |
| **Readability (Flesch)** | Mid → AI | AI clusters in the 40–60 readability band |

### Pipeline

```
Text → NLTK tokenisation → 11 features → StandardScaler → LinearSVC (Platt calibration) → P(AI)
```

The **bigram language model** (trained on 70% of NLTK's Brown corpus) provides the perplexity and burstiness signals. The classifier is compared against Logistic Regression and Random Forest via 5-fold stratified cross-validation; the best AUC winner is serialised.

### Browser inference

`frontend/lm.json` is the bigram LM serialised as JSON (`v`, `u`, `b` keys). The same feature extraction and Platt-calibrated LinearSVC are re-implemented in ~200 lines of vanilla JavaScript, enabling fully offline inference with no API call.

**Sigmoid fix:** sklearn's Platt scaling uses `P(class=1) = 1 / (1 + exp(A·f + B))`, which is *not* the same as `sigmoid(A·f + B)`. The frontend correctly applies this formula.

## Running locally

### Frontend only (no Python needed)

```bash
cd frontend
python -m http.server 8080
# visit http://localhost:8080
```

### Full backend

```bash
cd backend
pip install -r requirements.txt
# First run: builds LM + trains classifier automatically
uvicorn app:app --reload
```

API docs available at `http://localhost:8000/docs`

## Deployment

### Vercel (frontend)

Push to GitHub, import repo on Vercel, set **Root directory = `frontend`** — no build step needed.

### Render (backend)

`render.yaml` handles the build command (`python reference_lm.py && python train.py`) and start command. The lifespan hook in `app.py` also auto-builds on cold start.

### Hugging Face Spaces

`Dockerfile` at the repo root is configured for the HF Spaces container environment.

## Known limitations

> These are documented honestly to help readers interpret results correctly.

1. **Synthetic AI training corpus.** The `ai_samples.py` generator covers 6 stylistic registers (hedge/self-help, tech-jargon, academic, business, journalistic, listicle) but is *not* real LLM output. Test accuracy of 99%+ measures the train/test split on the *same synthetic distribution*, not real-world performance.  
   **Fix:** Replace with [HC3](https://huggingface.co/datasets/Hello-SimpleAI/HC3) or the [Kaggle LLM detection dataset](https://www.kaggle.com/competitions/llm-detect-ai-generated-text) and retrain — the feature pipeline and training code are data-agnostic.

2. **Sentence-level scores are noisy for short sentences.** The classifier was trained on paragraph-length chunks; applying it to 5-word sentences produces unreliable estimates. Treat sentence scores as directional indicators, not precise probabilities.

3. **Reference LM is 1960s English.** The Brown corpus has a different register from modern web text, which inflates perplexity for modern human writing. A contemporary reference corpus (Wikipedia, CommonCrawl) would improve signal quality.

4. **No rate limiting in the default config.** Add `slowapi` for production deployments.
